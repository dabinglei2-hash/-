# 妙想富文本、附件与完整备份提案

日期：2026-10-25；实施更新：2026-10-26。状态：**用户已明确批准方案 A；实现与实际验证见[交付报告](IDEAS-RICH-REPORT-20261026.md)**。

## 1. 现状与冲突

- 现有diary严格为`id,date,title,content,createdAt`五字段，content是非空纯文本，最多3000字；标签按recordId保存在原note-tags键。
- `saveIdea`复用原快照/冲突检查和多键回滚；草稿在内存及History，不是关闭浏览器后可靠的持久草稿。没有图片存储、富文本编辑器、OCR或账号/联系人。
- JSON v5–v8严格校验，不能直接给旧记录追加HTML、图片字段或偷偷把content改为HTML；图片放进localStorage会加剧容量风险。
- 本轮安全UI可独立完成：连续列表、去冗余信息/日期、图标返回、沉浸式文字面板、原标签/草稿暂存与安全退出。新增可持久化能力需依据AGENTS及lifeos-data-guard先确认。

## 2. 方案A（推荐）：可选扩展，不迁移历史

### 原数据

- 原七键、旧记录ID、日期、标题、创建时间和标签不迁移、不批量改写；旧content保持纯文本供原搜索/首页/导出读取。
- 编辑旧记录时保留隐藏的原日期/标题；新记录默认本地当天，标题默认为空。
- 原3000字正文上限保留；首版仍要求至少一字真实正文，不能以自动生成的假正文充当图片笔记。

### 富文本侧表（新增可选第八键）

拟新增`my-life-dashboard-ideas-meta-v1`：

```text
{version:1,documents:[{recordId,plainTextSnapshot,delta,attachmentIds,updatedAt}]}
```

- delta采用Quill Delta受限文档结构，只允许文本、加粗、下划线、浅黄高亮、有序列表、稳定本地图片引用。@名称为普通文本，标签仍用原独立关联。
- 读取时先核对recordId与plainTextSnapshot；若旧客户端已改正文，提示格式副本冲突，不能用过时格式覆盖正文。
- 严格校验插入内容/属性/大小/引用，禁止脚本、任意HTML、外部图片URL或不受支持的嵌入。预览与详情使用受限DOM渲染，不直接innerHTML用户内容。
- 新键只在明确保存富文本时写入；旧记录没有侧表时正常以纯文本编辑，无不可逆迁移。

### 图片与可靠草稿（本地IndexedDB）

拟新增数据库`lifeos-ideas-media-v1`（版本1），stores为`assets`、`drafts`、`pendingSaves`：

- assets存真实图片Blob、稳定ID、MIME、尺寸、字节数、摘要；正文侧表只存图片ID。展示使用临时Object URL，不把大图Base64放入localStorage。
- 首版每条最多3张；输入文件上限10MiB，解码/方向处理后生成最长边1600px、单张不超过1MiB的展示副本；本地总附件上限20MiB。原磁盘照片不改动。不支持/无法解码的图片给出原因，不假装成功。
- 拍照使用用户主动点击的文件输入`capture`，不自动开启摄像头；不支持时选择图片替代。不使用云存储。
- drafts存编辑上下文、正文/格式/标签/附件引用及更新时间；组合输入结束后防抖暂存，明确显示失败，关闭与刷新可恢复。发生冲突时保留草稿，不覆盖其他页面保存的记录。
- pendingSaves保存跨localStorage/IndexedDB的保存过程。先准备附件，再复用原记录/标签快照检查和多键回滚；失败保留草稿/准备附件供重试。刷新遇未完成操作先比对固定ID/内容，不自动覆盖或重复创建。
- 两种存储之间不具备统一数据库事务，不宣称绝对原子性。移除图片先改草稿引用，确认保存后再改记录关联，不自动清理共享/未知附件。

## 3. 备份兼容

- 原v5/v6/v7/v8导出按钮及格式保留，明确提示这些格式不含富文本/附件/新持久草稿。
- 新增完整v9，保留v8各分组，追加`ideasMeta`、`ideasAttachments`及`ideasDraft`；只在导出文件中将图片编码为Base64，包含MIME/尺寸/字节数/摘要供验证。
- v9上限40MiB，原v1–v8文件仍维持10MiB限制；原始数据过大时明确拒绝并保留原记录，不截断备份。
- 恢复兼容v1–v9，原预览/确认/相同跳过/冲突停止保留；检查附件真实字节、类型、摘要和引用，准备成功后再确认合并，不自动覆盖。
- 导入旧版不会清空现有富文本或图片；若旧正文与现有富文本快照冲突，停止并说明。新版带图片的完整恢复必须用v9及支持客户端。
- 必须在隔离浏览器验证纯文本旧备份、完整v9、重复导入、坏附件、冲突、空间不足、刷新中断及原模块数据不变后才视为完成。
