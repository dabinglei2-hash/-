# 日程数据扩展方案（A已批准，实施与验收中）

日期：2026-10-22。用户已明确批准方案A：独立元数据与v7完整备份。此记录保留决策边界；具体实施与测试结果见STATUS，不以批准代替验收。

## 当前约束与可先完成部分

`app.js` 严格校验任务的七个字段：`id,date,title,start,end,completed,createdAt`，位于 `my-life-dashboard-v1.tasks`。JSON v5/v6沿用严格字段校验。没有备注、优先级、独立截止日期、重复模板、实际执行起止时间。

不改结构即可完成：两个入口统一为“日程”，沿用 `#tasks` 与原任务详情；今日/日历/待办内部视图、月历、按计划时间排序的时间块、无时间任务分区、现有CRUD、时长快捷选择和时间重叠提示。计划时间不写入学习或收支。

## 两种方案

- **A：独立可选元数据（推荐）**。原五键、任务字段/ID和v5/v6保持不变。另加一键保存备注、优先级、独立截止日及重复规则，完整备份升级为显式v7。无需迁移旧记录；成本是增加关联校验、合并和完整恢复测试。
- **B：直接扩展任务模型**。给任务增加可选字段并重写所有严格校验、保存与备份兼容逻辑。元数据较集中，但影响原主记录与旧版客户端，回滚更复杂；本轮不推荐。

不批准扩展时，只实施上节的兼容核心；不提供无法保存的优先级/备注/重复控件，也不把计划日期冒充截止日。

## A方案的具体结构与行为

新增键（仅获批后使用）：`my-life-dashboard-schedule-meta-v1`。

```text
{
  version: 1,
  taskDetails: [{ taskId, priority, deadline, note }],
  series: [{ id, title, startDate, endDate, weekdays, start, end, active,
             priority, deadlineOffsetDays, note, createdAt, updatedAt }],
  occurrences: [{ seriesId, date, taskId, excluded }]
}
```

- priority为`low/medium/high`或代表未设置的null；deadline为有效`YYYY-MM-DD`或null，note为最多2000字纯文本。旧任务没有关联即显示“未设置优先级”、无截止日、无备注，不写默认值回旧任务。
- 重复规则仅每日/指定星期，起止日期必填且最多366天；`weekdays`为去重的1–7。只在用户确认“生成”后创建有限范围的普通任务，预览数量及重叠，不在渲染、启动或翻月时写记录。
- 同一`seriesId + date`只允许一个occurrence；先重新读取最新存储、检查冲突，再共同保存任务与元数据。普通任务仍是唯一任务数据源，新实例初始`completed:false`。
- 修改模板只影响下一次生成的缺失日期，不批量改写已有实例；已完成/历史任务保持原样。单独编辑不回写模板；删除某实例后保留excluded标记，防止再次生成。暂停模板不删除实例。
- `deadlineOffsetDays`为null或0–366整数，用实例计划日期加偏移计算其独立截止日；不反过来改任务日期。不增加实际执行字段，不伪造实际时长。
- 新字段严格类型、长度、引用、日期及重复键校验；用户文字仅按文本展示。

## 导出、恢复与回滚

- 原v5兼容与v6财务完整导出继续可用，并明确提示不含日程扩展；新增“完整JSON v7”包含`scheduleMeta`。保留v1–v6导入，不删除当前日程扩展。
- v7必须先验证任务引用与模板/实例唯一性，再预览、二次确认、安全合并。相同内容跳过；同一任务详情/模板/实例键不同内容时停止，不覆盖；无法确定语义时报告冲突。
- 复用现有多键保存/失败回滚并加入新键的读取保护；不宣称localStorage具备数据库原子事务。
- 扩展前对源码另建备份；真实数据只由用户在原来源导出。本机隔离合成环境验证旧备份、v7往返、重复生成、删除后再生成、模板变更及失败回滚。
- 回滚旧源码不会改旧任务；新元数据保留不删，但旧版界面不可见。v7在旧版导入器会被拒绝，不能宣称可向旧版完整恢复。
