# 统一学习模块：兼容扩展方案（方案 A 已批准）

日期：2026-10-22。用户已明确批准方案 A：独立元数据与 v8 完整备份；下文为获批边界。依据当前app.js、record-editor.js、insights.js及日程模块；不依据聊天推定实现。

## 实施前现状与无冲突部分

原学习记录严格为`id,date,content,duration,createdAt`，位于`my-life-dashboard-v1.studies`；duration为整数分钟，新增1–1440，旧0分钟记录可读取/编辑。首页和记录页均到`#learning`。日报通过studyRecordId关联同一数组，统计不能再加日报副本。原日程任务七字段及六个既有存储键保持不变；实施前JSON支持v1–v7。

不改结构即可统一入口、保留历史筛选/十条分页/原ID编辑与详情、新建学习工作台、展示按现有自然周/月口径计算的真实统计。

## 两种可行方案

- **A（推荐）：追加独立学习元数据和完整v8备份**。保留原六键、学习/日程字段及v5/v6/v7格式；新增可选键，承载目标、任务关联及可恢复的计时状态。不迁移或重写旧记录。
- **B：本轮仅完成入口、记录工作台和真实统计**。暂缓学习目标、计划持久化和专注计时，继续原v7完整备份。影响较小，但不能满足本轮完整功能。

## A的精确数据边界

新键：`my-life-dashboard-learning-meta-v1`。

```text
{
  version: 1,
  dailyGoals: [{ date, minutes }],
  plans: [{ taskId, estimatedMinutes, archived }],
  focusSessions: [{ id, taskId, title, date, status, accumulatedMs,
                    startedAt, endedAt, studyRecordId, recordDeleted,
                    createdAt, updatedAt }]
}
```

- dailyGoals按日期保存，minutes为1–1440整数；没设目标显示未设置，不补写旧日期。移除目标不删学习记录。
- plans只关联日程tasks的稳定ID，不复制任务标题、日期、完成状态或优先级；预计分钟1–1440。新建学习计划创建普通日程任务；优先级复用scheduleMeta.taskDetails，编辑保留任务ID/完成状态。不改变日程底层结构。关联已有日程须由用户选择，不能靠标题猜测。
- archived用于取消关联或保留已删除日程的历史关联。日程删除时只归档对应学习关联，不删实际学习或计时记录。学习中可明确取消关联，不静默删除日程。
- 学习计划完成状态就是原任务completed。结束计时不自动勾选计划，不自动增加收支。实际统计只读studies；预计分钟单独展示。
- 本轮实际学习记录仍保留原字段，不添加备注/起止时间字段。计时原始信息仅保存在可选元数据中。

## 计时、刷新与重复保存

- taskId可为null；主题沿用学习内容1–100字限制，长日程标题需用户调整计时主题，原日程标题不变。
- 状态为running/paused/ended/saved/cancelled。最多一个running、paused或ended的未解决计时；保存/取消后可开始下一次。取消须确认，保留取消状态和原始累计量，不创建学习记录。
- 开始、暂停、继续、结束时保存状态；运行秒表用累计毫秒加当前时间戳差计算，刷新/后台不依赖逐秒写入或累加。后台继续计时，离开模块提示；离开后可回来暂停/结束。
- startedAt仅running时是有效时间戳，其他状态为null；endedAt仅ended/saved/cancelled时有效。设备时钟早于起点时显示原因、停止生成实际记录，保留成果，不假造时长。
- date默认为计时开始的本地日期；结束后确认面板可以明确选择记录日期。跨日不自动拆分或按计划日期回填。
- **分钟规则**：计时保存按完整分钟向下取整，毫秒零头继续留在计时元数据；不足1分钟保留待保存状态，可继续计时，不默默生成0分钟或向上取整。超过单条1440分钟上限保留成果并提示手动拆分，不截断或自动写多条。
- 每次开始预留固定studyRecordId。结束后先持久化ended，再由用户确认生成该ID的普通学习记录及saved状态；重复点击/刷新/恢复不另生成ID。若中断后发现同ID相同记录，确认关联而不重复新增；同ID不同内容停止，不覆盖。
- 学习记录后续编辑仍走原功能，保留原ID；原始计时量不覆盖用户修改后的实际分钟。确认删除实际记录时标记recordDeleted，保留计时历史与ID，不因再打开旧计时而复活记录。

## v8备份、合并与失败处理

- v8在v7上追加learningMeta；保留原v5/v6/v7按钮与格式，并明确这些版本不包含学习扩展。v1–v7恢复不会清除现有学习扩展。
- **运行计时的导出策略**：仅在导出副本中，将运行段累计到导出瞬间并保存为paused；原页面继续计时。恢复后需手动继续，避免把备份存放数天的时间算作学习。v8中未冻结的running状态拒绝导入。
- 严格校验日期、整数分钟/毫秒、枚举、唯一ID、唯一日期/任务引用、状态组合及保留的删除标记；关联缺失只有明确归档/已删除历史引用可接受。
- 预览扩展数量和计时恢复策略，用户确认后安全合并。相同条目跳过；同日期目标、同任务计划、同计时ID不同内容均停止，不按时间较新覆盖。合并后出现两个未解决计时也停止。
- 复用现有多键保存及旧快照保护，失败保留输入并尝试回滚；不声称localStorage是数据库事务。固定studyRecordId用于检测跨键中断，不能以重启清空数据解决。
- 实施前已备份当前六个待改文件及摘要，保留未提交日程改动和旧JSON；只用新Chrome上下文及合成数据测试恢复、计时刷新、重复保存、冲突与失败。真实备份仍须用户在原来源导出。

回滚源码不会删除新元数据，但旧版无法完整读取v8，也不会维护学习扩展；代码备份不等于用户数据备份。不引入依赖、云服务、登录或部署。
