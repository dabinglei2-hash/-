更新：2026-10-26。当前备份标识：`main` / `v0.2.0-backup-2026-10-26`，涵盖收支连续列表、统计入口迁移、社交演示及妙想富文本/图片/草稿/OCR与完整v9；实际提交见[版本记录](VERSION_HISTORY.md)；验证状态见 [STATUS](STATUS.md)，实现机制见 [ARCHITECTURE](ARCHITECTURE.md)。

## 1. 产品定位

Life OS 是项目工作名，当前界面名称为“我的生活管理台”。面向主要用手机、没有编程基础的个人用户，把学习、外卖与日常收支、任务、想法和成长放在一个本地生活管理入口中。

核心体验：打开首页约 5 秒理解所选日期状态；通过快捷入口或完整今日回顾，在约 3–5 分钟内完成常用记录。这是产品目标，尚无可用性研究证明达标。

现阶段单人、本地优先、中文、USD。本轮获准提供隔离的社交前端演示；不新增真实社交后端、金融服务或登录系统。

## 3. 已锁定的业务规则

- 所有摘要基于记录实际填写的日期，不能按创建时间把历史数据归入今天。妙想的列表创建时间排序不改变记录日期。
- 财务为 USD，合计主要以整数分计算；差额＝收入−支出。旧混合账单、ID、分类快照和日报引用不能拆散或批量改写。
- 统计周为周一至周日；历史列表“近7天”为截至参考日的7天，两种口径并存，不能偷偷统一。月/年为自然月/年。
- 日均＝所选指标总额÷完整周期自然日数，包含未来日期：7、28–31、365/366天。无财务记录显示“—”，不是一笔零元交易。
- 统计只汇总主学习/收支/任务数组，日报副本不再加一次。任务完成率为四舍五入的百分比；0任务为0%。
- 旧记录无分类/标签时正常显示“未分类”/无标签，不猜测、不迁移历史正文。具体严格格式以代码校验为准。
- 资料净积累是累计收支差额；资产页净资产是手动资产减负债，两者不能混用或自动互写。
- 日程计划时间不等于实际执行；完成学习计划/外卖班次不自动创建学习或账单。任务日期仍是计划日期，独立截止日不替换它；不凭旧时间推断实际时长。
- 2026-10-22用户批准[日程方案A](SCHEDULE-EXTENSION-PROPOSAL.md)：旧五键与任务七字段保留，可选第六键和v7完整备份承载扩展，无批量迁移或渲染时自动生成。拖动排程、实际计时、通知与妙想自动转待办不在本轮范围。

- 2026-10-22用户批准[学习方案A](LEARNING-EXTENSION-PROPOSAL.md)：原六键及学习/任务字段保留，第七可选键保存目标、任务关联与计时，v8完整备份承载扩展。计划不算实际，计时不自动完成日程；完整分钟向下取整，零头保留，不足1分钟不生成记录。运行计时仅在导出副本暂停，恢复后手动继续；同身份冲突停止。
- 学习第一版不新增备注/起止字段、课程系统、云计时、排行榜或社交；三个参考仓库仅借鉴可核实的交互思路，不引入其框架或不明许可代码。

- 2026-10-23用户选择个人中心方案A：本轮只完善现有能力及安全UI；保留USD、首字头像、浅色和周一规则。图片头像、可切换主题/货币/周起始日、持久备份时间均未实施，不增加无效开关。不把历史USD换符号解释成人民币。
- 成长入口打开当天学习统计；财富入口打开当月收支，沿用来源返回及五主导航。累计净结余与手动账户/资产分开。备份只表示已发起浏览器下载，文件实际保存/可恢复由下载检查及恢复演练确认；不虚构自动备份或最近备份时间。

## 4. 视觉与交互验收方向

采用接近 Apple/iOS 的安静、轻量体验，不宣称已通过官方人机界面规范认证：

- 黑白灰、浅底、统一圆角/文字层级、轻阴影和细线图标；复用现有 Tokens、卡片、列表、Sheet、Toast、返回栏。
- 手机固定五入口：首页、记录、收支、社交、我的；桌面保留左侧导航。学习/任务/妙想是二级页面，不重复加主入口。
- 普通点击区≥44×44 CSS px，输入清晰，图标有名称、焦点和状态；保留减少动态效果设置。
- 安全区、软键盘、短屏下操作可到达；列表可局部滚动，不靠缩字或藏功能强制一屏。
- 默认、空数据、长金额/分类、保存失败、重复提交、缺失记录都有明确反馈；不放假数据或无结果的假按钮。

## 6. 每轮验收底线

1. 真实数据不变，代码回滚与 JSON 恢复路径明确；版本兼容和冲突不覆盖。
2. 相关新增/编辑/删除确认、重复保存、刷新读取、统计和导出/恢复在隔离数据下验证。
3. 导航来源、返回/前进、详情刷新和过滤/分页状态符合实际路径。
4. UI至少检查375/390/414px、短屏和1366px桌面；320/430px为补充边界。模拟结果与实机结果分别记录。
5. 不引入本轮 JavaScript 错误；失败保留输入及原因。未执行项目写入 STATUS，不能称通过。

需求变更在此写决定与边界，实施结果和风险写入 STATUS，避免把待办描述误写为已完成。
